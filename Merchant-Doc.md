## 1. How it works

Your app never talks to Apple's payment servers or handles card data. The SDK opens a short session with the gateway, shows the Apple Pay sheet, and hands the encrypted Apple Pay token to the gateway, which decrypts and processes it.

```
Your page/app ── SDK ──► POST /v1/session            (gateway returns merchant ID, networks, session token)
                     ──► Apple Pay sheet
                     ──► POST /v1/validate-merchant  (web only — gateway asks Apple to validate your domain)
                     ──► customer approves (Face ID / Touch ID)
                     ──► POST /v1/payments           (encrypted token → gateway → PaymentResponse)
```

## 2. Before you start

Get the following from your gateway provider:

| Item | Example | Used for |
|---|---|---|
| Sandbox API key | `pk_sandbox_…` | Testing against UAT |
| Production API key | issued at go-live | Live payments |
| Apple merchant ID | the `appleMerchantId` the gateway returns | Web capability checks; iOS entitlement |
| Gateway base URL | one for sandbox and one for production, e.g. `https://gateway.example.com/sdk/applepay` | `baseUrl` / `baseURL` option |

Keep API keys out of source control (environment files, xcconfig, CI secrets) and never commit them.

**Amounts are integers in minor units.** `amount: 1000` with `currency: "MNT"` is ₮10.00. The SDK converts to Apple Pay's decimal format for you.

## 3. The payment request and response

The same shape is used on every platform.

### PaymentRequest

| Field | Type | Required | Notes |
|---|---|---|---|
| `reference` | string (1–64) | ✓ | Your order ID; shown in the gateway |
| `total` | `{ currency, amount }` | ✓ | ISO-4217 currency (e.g. `MNT`), integer minor units |
| `countryCode` | string (2) | ✓ | Merchant country, e.g. `MN` |
| `description` | string (≤ 280) | | |
| `lineItems` | `[{ label, amount, type? }]` | | `type`: `final` (default) or `pending` |
| `supportedNetworks` | `visa`, `mastercard`, `amex`, `discover`, `interac`, `jcb`, `unionpay`, `mada`, `elo` | | Defaults to the networks the gateway returns — leave unset unless you must restrict |
| `supportedCountries` | string[] | | Restrict card issuing countries |
| `requiredBillingContactFields` / `requiredShippingContactFields` | `postalAddress`, `name`, `phoneNumber`, `emailAddress` | | |
| `idempotencyKey` | UUID | | Generated by the SDK if omitted; set it yourself to make retries of the same order safe |
| `metadata` | `{ [key]: string }` | | Free-form data stored with the payment |

### PaymentResponse

| Field | Notes |
|---|---|
| `id` | Gateway payment ID |
| `status` | `AUTHORIZED`, `CAPTURED`, `PENDING`, `DECLINED`, `FAILED` |
| `reference`, `total` | Echo of the request |
| `authorizedAt` | ISO timestamp |
| `authorizationCode` | When authorized |
| `declineReason` | When declined |
| `environment` | `sandbox` or `production` |

## 4. Web — `@gateway/pay-web`

### 4.1 Requirements

- Your checkout page is served over **HTTPS** from a domain that is **registered and verified** for Apple Pay (§4.2). `localhost` and unverified domains cannot complete a payment.
- Customers use Safari on macOS/iOS, or another browser that supports Apple Pay JS.
- The gateway must accept browser requests from your origin (CORS). Give your gateway provider every origin that will call the SDK.

### 4.2 Domain verification (one time per domain)

Apple only lets the gateway start a payment session for domains verified under its merchant ID. Each domain and subdomain is verified separately (`shop.example.mn` and `www.example.mn` are two domains).

1. **Request the domain association file** from your gateway provider for each domain you will take payments on. It is specific to the gateway's merchant ID — a file from another provider or another merchant ID will not work.
2. **Host it** at exactly:
   ```
   https://<your-domain>/.well-known/apple-developer-merchantid-domain-association
   ```
   - The file name has **no extension** (not `.txt`).
   - Serve the file content unchanged, with HTTP **200**.
   - No redirects, no login, no IP allow-listing — Apple's servers fetch it from the public internet.
   - A valid, publicly trusted TLS certificate is required.
3. **Check it** from outside your network:
   ```bash
   curl -i https://<your-domain>/.well-known/apple-developer-merchantid-domain-association
   ```
   Expect `HTTP 200` and the file content straight away.
4. **Tell your gateway provider** the domain so they register and verify it with Apple and add it to the gateway's allowed domains.
5. **Leave the file in place.** Apple re-checks verified domains periodically; removing it later breaks payments.

### 4.3 Install

```bash
npm install @gateway/pay-web @gateway/pay-core
```

(`pnpm add` / `yarn add` work the same way.)

### 4.4 Content Security Policy

If your site sets a CSP, allow:

- `script-src https://applepay.cdn-apple.com` — Apple's button script loaded by `loadApplePaySDK()`
- `connect-src https://gateway.example.com` (your gateway host) — gateway API calls

### 4.5 Integrate with the ready-made button (recommended)

```ts
import { GatewayPay, loadApplePaySDK, createApplePayButton } from "@gateway/pay-web";
import type { PaymentResponse } from "@gateway/pay-core";

const pay = new GatewayPay({
    apiKey: import.meta.env.VITE_GATEWAY_API_KEY,         // your sandbox / production key
    environment: "sandbox",                               // "production" when live
    baseUrl: import.meta.env.VITE_GATEWAY_BASE_URL,       // required; there is no default host
    // domainName defaults to window.location.hostname — must be a verified domain
});

await loadApplePaySDK(); // registers Apple's <apple-pay-button> element

const button = await createApplePayButton({
    sdk: pay,
    merchantIdentifier: "<appleMerchantId from your gateway provider>",
    request: () => ({
        reference: order.id,
        total: { currency: "MNT", amount: order.totalMinor },
        countryCode: "MN",
        description: order.summary,
    }),
    style: "black",          // "black" | "white" | "white-outline"
    type: "buy",             // "buy", "check-out", "pay", "donate", …
    locale: "en-US",
    onSuccess: (r: PaymentResponse) => showReceipt(r),
    onCancel: () => showMessage("Payment cancelled"),
    onError: (e) => showMessage(String(e)),
});

if (button) {
    document.querySelector("#apple-pay-container")!.appendChild(button);
} else {
    // Apple Pay not available in this browser — show your other payment methods
}
```

Size the button with CSS:

```css
apple-pay-button {
    --apple-pay-button-width: 220px;
    --apple-pay-button-height: 44px;
    --apple-pay-button-border-radius: 8px;
    display: inline-block;
}
```

### 4.6 Integrate with your own button

```ts
if (!pay.canMakePayments()) {
    hideApplePay();
} else {
    myButton.addEventListener("click", async () => {
        try {
            const response = await pay.authorize({
                reference: order.id,
                total: { currency: "MNT", amount: order.totalMinor },
                countryCode: "MN",
            });
            showReceipt(response);
        } catch (err) {
            handleError(err); // GatewayError — see §7
        }
    });
}
```

Call `authorize()` **directly inside the click handler** — Safari only opens the sheet from a user gesture. Don't `await` other work before it.

`getApplePayCapabilities(merchantIdentifier)` returns `paymentCredentialsAvailable`, `paymentCredentialsUnavailable`, `paymentCredentialStatusUnknown` or `applePayUnsupported`; use `shouldShowApplePayButton(status)` to decide whether to show Apple Pay at all.

## 5. iOS — `GatewayPaySDK`

### 5.1 Requirements

- iOS 15+, Xcode 16+.
- A paid Apple Developer Program membership (free teams can't use Apple Pay).
- Apple Pay inside apps has **no domain verification**. Instead, the merchant ID must be in your app's entitlements and the gateway must hold the Payment Processing certificate for it.

### 5.2 Apple Developer setup (one time)

1. **Merchant ID.** In Certificates, Identifiers & Profiles → Identifiers → Merchant IDs, create one (e.g. `merchant.mn.yourshop`), or use the one your gateway provider assigns you. It must be in the **same Apple team** that signs your app.
2. **Payment Processing certificate.** The gateway decrypts your Apple Pay tokens, so the certificate's private key must stay with the gateway provider:
   1. Ask your gateway provider for a CSR (certificate signing request) for your merchant ID.
   2. In the merchant ID's page → Apple Pay Payment Processing Certificate → Create Certificate, upload that CSR.
   3. Download the issued `.cer` and send it to your gateway provider.
3. **Register the merchant ID with your gateway provider** so `POST /v1/session` returns it as `appleMerchantId`. The SDK uses that value for the Apple Pay request, and it must match your entitlement exactly.
4. **App ID.** On your app's identifier, enable **Apple Pay Payment Processing** and select the merchant ID.

### 5.3 Xcode setup

1. Target → **Signing & Capabilities** → **+ Capability** → **Apple Pay**, tick your merchant ID. This writes `com.apple.developer.in-app-payments` to your `.entitlements` file:
   ```xml
   <key>com.apple.developer.in-app-payments</key>
   <array>
       <string>merchant.mn.yourshop</string>
   </array>
   ```
2. Add the SDK:
   - **Swift Package Manager:** File → Add Package Dependencies → Add Local… → select the `pay-ios` folder from the SDK distribution from your gateway provider (it contains `Package.swift`), and add the `GatewayPaySDK` library to your app target.
   - **CocoaPods:** in your `Podfile`
     ```ruby
     pod 'GatewayPaySDK', :path => '<path to pay-ios>'
     ```
     then run:
     ```bash
     pod install
     ```
     and open the `.xcworkspace`.

   Use one method only — linking the SDK both ways causes duplicate-module errors.
3. Store the API key outside source code, e.g. an `xcconfig` file excluded from git, referenced from `Info.plist`.

### 5.4 Integrate

```swift
import SwiftUI
import PassKit
import GatewayPaySDK

final class CheckoutModel: ObservableObject {
    @Published var status = ""

    private let sdk = GatewayPaySDK(
        apiKey: AppConfig.gatewayKey,
        environment: .sandbox,                    // .production when live
        baseURL: AppConfig.gatewayBaseURL         // required; there is no default host
    )

    var canPay: Bool { GatewayPaySDK.canMakePayments() }

    func pay(order: Order) {
        let request = PaymentRequest(
            reference: order.id,
            total: Money(currency: "MNT", amount: order.totalMinor),
            countryCode: "MN",
            description: order.summary
        )

        sdk.authorize(request) { result in
            DispatchQueue.main.async {                // completion may arrive off the main thread
                switch result {
                case .success(let response):
                    self.status = "\(response.status.rawValue) \(response.id)"
                case .failure(let error) where error.code == .userCancelled:
                    self.status = "Cancelled"
                case .failure(let error):
                    self.status = error.description   // "[CODE] message"
                }
            }
        }
    }
}
```

Show Apple's button with `PKPaymentButton` (wrap it in `UIViewRepresentable` for SwiftUI) and only when `GatewayPaySDK.canMakePayments()` is `true`. The completion handler is called exactly once.

## 6. React Native — `@gateway/pay-react-native`

### 6.1 Requirements

- React Native 0.75+, iOS 15+.
- The same Apple Developer and Xcode setup as native iOS: §5.2 and step 1 of §5.3 (merchant ID, Payment Processing certificate, Apple Pay capability).
- **Android:** there is no Apple Pay. The SDK opens your `webCheckoutUrl` in the browser and then rejects with `APPLE_PAY_UNAVAILABLE`; complete those payments through your web checkout.

### 6.2 Install

```bash
npm install @gateway/pay-react-native @gateway/pay-core
```

The iOS bridge is autolinked. It depends on the `GatewayPaySDK` pod, so add it to `ios/Podfile` inside your app target:

```ruby
pod 'GatewayPaySDK', :path => '<path to pay-ios>'
```

Then install pods:

```bash
cd ios && pod install
```

### 6.3 Integrate

```tsx
import { GatewayPay, ErrorCode } from "@gateway/pay-react-native";

const pay = new GatewayPay({
    apiKey: Config.GATEWAY_API_KEY,
    environment: "sandbox",                               // "production" when live
    baseUrl: Config.GATEWAY_BASE_URL,                     // required; there is no default host
    webCheckoutUrl: "https://shop.example.mn/checkout",   // used on Android
});

async function onPayPress(order: Order) {
    if (!(await pay.canMakePayments())) return showOtherMethods();
    try {
        const response = await pay.authorize({
            reference: order.id,
            total: { currency: "MNT", amount: order.totalMinor },
            countryCode: "MN",
        });
        showReceipt(response);
    } catch (err) {
        // On iOS the error comes from the native module: an Error whose `code` is the gateway code.
        if ((err as { code?: string }).code === ErrorCode.UserCancelled) return;
        showError(err);
    }
}
```

Request validation errors and the Android fallback throw a JS `GatewayError`; errors from the iOS native module are React Native `Error`s carrying the same `code` string — so check `code` rather than `instanceof`.

The package re-exports everything from `@gateway/pay-core` (types, `GatewayError`, `ErrorCode`). Create `GatewayPay` once (e.g. with `useMemo` or at module level) — the constructor configures the native module.

## 7. Errors

The web and iOS SDKs fail with a `GatewayError` that has a `code`, a `message`, and where available `httpStatus` and `requestId` (quote `requestId` when contacting support). In React Native on iOS, the rejection is an `Error` with the same `code` (see §6.3).

| Code | Meaning | What to do |
|---|---|---|
| `USER_CANCELLED` | Customer closed the sheet | Do nothing / let them retry |
| `APPLE_PAY_UNAVAILABLE` | No Apple Pay on this device/browser, no eligible card, or (iOS) entitlement doesn't match the merchant ID | Offer another payment method; check your setup |
| `VALIDATION_FAILED` | The request failed validation (client or gateway) | Fix the field named in the message |
| `INVALID_API_KEY` | Key missing, wrong or revoked | Check the key and environment |
| `SESSION_EXPIRED` | Gateway session expired | Start the payment again |
| `DECLINED` | Issuer declined (iOS maps HTTP 402) | Ask for another card |
| `RATE_LIMITED` | Too many requests | Retry later |
| `NETWORK_ERROR` / `TIMEOUT` | Connectivity problem (the web SDK retries these automatically) | Ask the customer to retry |
| `INTERNAL` | Any other gateway error | Retry; contact your gateway provider with `requestId` if it persists |

A successful `authorize()` can still return `status: "DECLINED"` or `"FAILED"` — always check `response.status` before treating the order as paid.

## 8. Testing

1. Use the **sandbox** API key, `environment: "sandbox"` and the sandbox base URL.
2. **Web:** test on your verified domain (a staging subdomain verified per §4.2), not `localhost`.
3. **iOS / React Native:** test on a **real iPhone**. The simulator's "Simulated Instrument" produces an empty token that the gateway cannot decrypt.
4. Use an Apple **sandbox tester** account (App Store Connect → Users and Access → Sandbox), sign in on the device (Settings → Developer → Sandbox Apple Account), and add one of Apple's published sandbox test cards to Wallet. Don't use real cards for testing.
5. Test success, cancel (close the sheet), and a declined card.

## 9. Go-live checklist

- [ ] Production API key received and stored as a secret
- [ ] `environment` set to `production` and the production base URL
- [ ] **Web:** every production domain hosts the association file and is verified by your gateway provider; CSP allows Apple's script and the gateway
- [ ] **iOS / RN:** Payment Processing certificate issued for your merchant ID and delivered to your gateway provider; entitlement matches the `appleMerchantId` the production gateway returns
- [ ] Apple Pay button follows Apple's [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/apple-pay)
- [ ] `response.status` checked before fulfilling orders; `reference` stored with your order
- [ ] A small live transaction completed and reconciled with your gateway provider
