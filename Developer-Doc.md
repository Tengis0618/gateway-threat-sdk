## 1. Repository layout

pnpm 9 workspace driven by Turborepo. Workspaces: `apps/*`, `packages/*`, `tooling/*`.

| Path | Name | What it is | Build output |
|---|---|---|---|
| `packages/core` | `@gateway/pay-core` | Shared types, `GatewayError`, zod validation, `HttpClient` | `dist/` (tsup, ESM + CJS + d.ts) |
| `packages/pay-web` | `@gateway/pay-web` | Apple Pay on the web (`ApplePaySession`) | `dist/` (tsup) |
| `packages/pay-react-native` | `@gateway/pay-react-native` | RN wrapper over the iOS SDK | `lib/` (react-native-builder-bob) |
| `packages/pay-ios` | `GatewayPaySDK` | Native Swift SDK (PassKit) | SwiftPM / CocoaPods |
| `apps/example-web` | `example-web` | Vite demo page | `dist/` |
| `apps/example-ios` | — | SwiftUI demo (project generated by XcodeGen) | — |
| `apps/example-rn` | `example-rn` | React Native demo | — |
| `tooling/` | — | Shared `tsconfig` presets and ESLint config | — |

Dependency direction: `pay-web` and `pay-react-native` depend on `pay-core` (`workspace:` protocol). `pay-react-native`'s iOS bridge depends on the `GatewayPaySDK` pod. The Swift SDK re-implements pay-core's models, errors and retry logic natively — **an API contract change must be made in both TypeScript and Swift.**

| Tool | Version | Needed for |
|---|---|---|
| Node.js | ≥ 20.10 | everything JS |

```bash
corepack enable
```

## 3. First-time setup

1. Clone the repository and open a terminal at the repo root.
2. Install all workspace dependencies:
   ```bash
   pnpm install
   ```
3. Build every package once (later builds are cached by Turborepo):
   ```bash
   pnpm build
   ```

## 4. Workspace-wide commands

Run from the repo root.

| Command | What it does |
|---|---|
| `pnpm build` | `turbo run build` — builds all packages; dependencies (`pay-core`) build first |
| `pnpm dev` | `turbo run dev --parallel` — watch mode for every package that has a `dev` script |
| `pnpm lint` | `turbo run lint` (only `packages/core` defines `lint` today) |
| `pnpm format` | Prettier over `ts, tsx, js, jsx, json, md, yml, yaml` |
| `pnpm turbo run test` | Runs every package's tests (no root `test` script) |
| `pnpm turbo run typecheck` | `tsc --noEmit` in every package (no root `typecheck` script) |
| `pnpm clean` | Removes build outputs and the root `node_modules` |
| `pnpm --filter <name> <script>` | Runs one package's script, e.g. `pnpm --filter @gateway/pay-web test` |

TypeScript is strict (`tooling/tsconfig/base.json`) with `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` — pass optional fields with a conditional spread (`...(x !== undefined && { x })`) rather than as `undefined`.

## 5. packages/core — `@gateway/pay-core`

Shared contract for the JS SDKs: types (`PaymentRequest`, `PaymentResponse`, `MerchantSession`, `Environment`), `GatewayError` + `ErrorCode`, zod schemas + `validate()`, and `HttpClient` (Bearer auth, `Idempotency-Key`, SDK identification headers, retry with backoff on network errors/timeouts).

1. Build:
   ```bash
   pnpm --filter @gateway/pay-core build
   ```
2. Watch while developing:
   ```bash
   pnpm --filter @gateway/pay-core dev
   ```
3. Run tests (vitest):
   ```bash
   pnpm --filter @gateway/pay-core test
   ```
4. Run a single test file / test name:
   ```bash
   pnpm --filter @gateway/pay-core exec vitest run src/http/__tests__/retry.test.ts -t "<test name>"
   ```
5. Type-check and lint:
   ```bash
   pnpm --filter @gateway/pay-core typecheck
   ```
   ```bash
   pnpm --filter @gateway/pay-core lint
   ```

Notes: tsup builds with `tsconfig.tsup.json` (the regular `tsconfig.json` is composite). `baseUrl` is a required option, so no gateway host is built in. Headers are in `src/http/headers.ts`; `headerPrefix` sets the prefix of the two identification headers (default `X-Pay`).

## 6. packages/pay-web — `@gateway/pay-web`

`GatewayPay` class (`authorize()`, `canMakePayments()`), `getApplePayCapabilities()`, `loadApplePaySDK()` and `createApplePayButton()`. Unlike the RN package it does **not** re-export `@gateway/pay-core`, so types such as `PaymentRequest` and `GatewayError` are imported from `@gateway/pay-core`.

1. Build the package together with its dependencies (the trailing `...` selects `pay-core` too):
   ```bash
   pnpm --filter @gateway/pay-web... build
   ```
2. Watch:
   ```bash
   pnpm --filter @gateway/pay-web dev
   ```
3. Test (vitest + jsdom):
   ```bash
   pnpm --filter @gateway/pay-web test
   ```
4. Single test:
   ```bash
   pnpm --filter @gateway/pay-web exec vitest run src/__tests__/GatewayPay.test.ts -t "<test name>"
   ```
5. Type-check:
   ```bash
   pnpm --filter @gateway/pay-web typecheck
   ```

Key files: `src/GatewayPay.ts` (session → validate-merchant → payments flow), `src/applepay/request.ts` (builds the `ApplePayPaymentRequest`, maps network names such as `mastercard` → `masterCard`, converts minor units to decimal strings).

## 7. packages/pay-react-native — `@gateway/pay-react-native`

JS wrapper (`src/index.ts`) + iOS bridge (`ios/GatewayPayModule.{swift,m}`, podspec `GatewayPayReactNative.podspec`, depends on the `GatewayPaySDK` pod). On Android it only opens `webCheckoutUrl`; a native Android SDK is deferred.

1. Build (`lib/commonjs`, `lib/module`, `lib/typescript`):
   ```bash
   pnpm --filter @gateway/pay-react-native build
   ```
2. Test (jest, `react-native` preset — `@gateway/pay-core` is mapped to its source, so core does not need to be built):
   ```bash
   pnpm --filter @gateway/pay-react-native test
   ```
3. Single test:
   ```bash
   pnpm --filter @gateway/pay-react-native exec jest src/__tests__/index.test.ts -t "<test name>"
   ```
4. Type-check:
   ```bash
   pnpm --filter @gateway/pay-react-native typecheck
   ```

`baseUrl` and `headerPrefix` are passed through `configure()` to the Swift SDK.

## 8. packages/pay-ios — `GatewayPaySDK`

Swift package (`Package.swift`, swift-tools 6.0, iOS 15+) and CocoaPods podspec. Entry point `GatewayPaySDK(apiKey:environment:baseURL:headerPrefix:)` → `ApplePayCoordinator` (PassKit). Endpoints in `Networking/Endpoints.swift`.

All steps on macOS, from `packages/pay-ios`.

1. Build for the Mac host (quick compile check):
   ```bash
   swift build
   ```
   `swift build`/`swift test` compile for **macOS**, not iOS. PassKit has macOS-only requirements (e.g. `presentationWindow(for:)`), guarded with `#if os(macOS)` in the source.
2. Run the tests:
   ```bash
   swift test
   ```
3. Run one test class or method:
   ```bash
   swift test --filter RetryTests
   ```
4. Build for iOS (what apps actually use):
   ```bash
   xcodebuild -scheme GatewayPaySDK -destination 'generic/platform=iOS Simulator' build
   ```

Debug logging: failed HTTP responses are logged through `os.Logger` (subsystem `com.yourgateway.pay`, category `network`) with the request headers (API key redacted), response headers and the first 1000 bytes of the body. They show in Xcode's debug console.

## 9. apps/example-web

Vite page that renders Apple's `<apple-pay-button>` and calls `GatewayPay.authorize()`. Served over HTTPS on port 5173. When `VITE_GATEWAY_BASE_URL` is a relative path, requests under it are proxied to `GATEWAY_PROXY_TARGET`.

1. Create local HTTPS certificates (Apple Pay requires HTTPS). From `apps/example-web`:
   ```bash
   mkcert -install
   ```
   ```bash
   mkdir -p .certs && cd .certs && mkcert localhost 127.0.0.1 ::1
   ```
   This produces `.certs/localhost+2.pem` and `.certs/localhost+2-key.pem`, which `vite.config.ts` loads. `.certs/` is git-ignored.
2. Configure the gateway:
   ```bash
   cp .env.example .env.local
   ```
   Set `VITE_GATEWAY_API_KEY`, `VITE_GATEWAY_BASE_URL` and `GATEWAY_PROXY_TARGET` in `.env.local` (git-ignored). `VITE_GATEWAY_HEADER_PREFIX` is optional.
3. Start the dev server from the repo root:
   ```bash
   pnpm --filter example-web dev
   ```
4. Open `https://localhost:5173` in **Safari** (macOS with Touch ID or a paired iPhone, or iOS).
5. Production build / preview:
   ```bash
   pnpm --filter example-web build
   ```
   ```bash
   pnpm --filter example-web preview
   ```

Limits of `localhost`: the gateway validates the merchant against its verified domain (`initiativeContext`), and Safari refuses a merchant session whose domain doesn't match the page. A full payment therefore cannot complete on `localhost`. To test end to end, serve the page from a domain verified for the merchant ID — e.g. register a dev subdomain, point it to `127.0.0.1` in your hosts file, issue an mkcert certificate for that name, and set `server.host` and the certificate paths in `vite.config.ts`.

## 10. apps/example-ios

SwiftUI demo. The Xcode project is generated from `project.yml` by XcodeGen; it compiles `ExampleApp/` in place and links `../../packages/pay-ios` as a local Swift package, so edits to the app or SDK appear on the next build.

All steps on macOS, from `apps/example-ios`.

1. Install XcodeGen:
   ```bash
   brew install xcodegen
   ```
2. Configure the gateway:
   ```bash
   cp Secrets.example.xcconfig Secrets.xcconfig
   ```
   Fill in `Secrets.xcconfig` (git-ignored): `GATEWAY_API_KEY`, `GATEWAY_BASE_URL`, the optional `GATEWAY_HEADER_PREFIX`, `GATEWAY_MERCHANT_ID` (the `appleMerchantId` returned by `/v1/session`), `GATEWAY_BUNDLE_ID` (an App ID with Apple Pay enabled and linked to the merchant ID) and `GATEWAY_DEVELOPMENT_TEAM`. Write URLs as `https:/$()/host`, because xcconfig treats `//` as a comment. Setting `GATEWAY_KEY`, `GATEWAY_BASE_URL` or `GATEWAY_HEADER_PREFIX` under Product → Scheme → Edit Scheme → Run → Environment Variables takes priority when launched from Xcode.
3. `project.yml`, `Info.plist` and the entitlements read these values, so they don't need editing.
4. Re-run the next step after changing the bundle ID, team or merchant ID.
5. Generate and open the project:
   ```bash
   xcodegen generate
   ```
   ```bash
   open ExampleApp.xcodeproj
   ```
6. Pick a simulator or a device and press ⌘R.

Re-run `xcodegen generate` after adding/removing files or editing `project.yml`. Open the `.xcodeproj` (not a `.xcworkspace`) and don't run `pod install` — this path uses SwiftPM. The CocoaPods path is described in `apps/example-ios/README.md`.

Simulator vs device: the simulator presents the sheet with a "Simulated Instrument" whose token has empty `paymentData`, so the backend cannot decrypt it. Use a real iPhone signed into an App Store Connect sandbox tester with an Apple sandbox test card to exercise decryption.

## 11. apps/example-rn

React Native 0.75 demo of `@gateway/pay-react-native`.

1. Install dependencies (repo root `pnpm install` covers this).
2. Configure the gateway, from `apps/example-rn`:
   ```bash
   cp .env.example .env.local
   ```
   ```bash
   cp ios/Secrets.example.xcconfig ios/Secrets.xcconfig
   ```
   Fill in both files (git-ignored). `.env.local` holds the JS values, which `scripts/generate-env.js` writes to the git-ignored `env.generated.ts` when you run `start`, `ios` or `typecheck`. `ios/Secrets.xcconfig` holds the merchant ID, bundle ID and team, which the Podfile includes in the project's build settings.
3. Install pods (the Podfile pulls `GatewayPaySDK` from `../../../packages/pay-ios`):
   ```bash
   cd ios && pod install && cd ..
   ```
4. Start Metro, then run on iOS:
   ```bash
   pnpm --filter example-rn start
   ```
   ```bash
   pnpm --filter example-rn ios
   ```

## 12. Backend endpoints the SDKs call

The gateway URL is always supplied by the caller as `baseUrl` (web, React Native) or `baseURL` (iOS), including any path prefix such as `/sdk/applepay`.

| Step | Method + path | Body | Response | Web | iOS |
|---|---|---|---|---|---|
| 1 | `POST /v1/session` | none (web) / `{}` (iOS) | `MerchantSession` (`sessionToken`, `appleMerchantId`, `displayName`, `supportedNetworks`, `merchantCapabilities`, `expiresAt`, `environment`) | ✓ | ✓ |
| 2 | `POST /v1/validate-merchant` | `{validationURL, domainName, displayName}` | `{merchantSession}` (JSON string from Apple) | ✓ | — (PassKit handles it) |
| 3 | `POST /v1/payments` | `{request, token, sessionToken}` | `PaymentResponse` | ✓ | ✓ |

Every request sends `Authorization: Bearer <key>`, `Content-Type`/`Accept: application/json`, `Idempotency-Key`, `X-Pay-Gateway` and `X-Pay-Version` (`headerPrefix` replaces the `X-Pay` part). HTTP status mapping: 401 → `INVALID_API_KEY`, 403 → `SESSION_EXPIRED`, 422 → `VALIDATION_FAILED`, 429 → `RATE_LIMITED` (iOS also 402 → `DECLINED`), anything else → `INTERNAL`.

## 13. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Safari: "This website does not accept the cards that you have added to Wallet" | `merchantCapabilities` contains `supportsCredit` without `supportsDebit` (debit cards filtered out), or the networks don't match the card. Send `["supports3DS"]`. |
| Backend: `400 The SSL certificate error` from Apple | The call to Apple's `startSession` isn't presenting the **Merchant Identity** certificate (missing, wrong cert, no private key, or stripped by an egress proxy). |
| Backend: `417 mass_enablement_authorization_denied` | Merchant ID / certificate / domain don't belong together: merchant ID in the request differs from the certificate's, or the domain isn't verified for that merchant ID. |
| Sheet closes with "Payment Not Completed" on `localhost` | Merchant session is bound to the verified domain; serve the page from that domain (see §9). |
| iOS `[APPLE_PAY_UNAVAILABLE]` immediately | Entitlements don't contain the `appleMerchantId` returned by `/v1/session`, App ID not linked to it, or no eligible card. |
| iOS `[INTERNAL] HTTP 406` | Server can't satisfy the `Accept` header — check the exact header in the Xcode console log (a typo here caused a 406). |
| iOS `[INTERNAL] The provided API key was rejected` | Placeholder key in use; set `Secrets.xcconfig` or `GATEWAY_KEY`. The backend returns a non-401 status for this, hence `INTERNAL`. |
| Backend: `Payment data decryption error: No content found` | Simulator token (empty `paymentData`). Test on a device. |
| `swift build` fails with a missing `presentationWindow(for:)` | Building for the macOS host; keep macOS-only delegate methods behind `#if os(macOS)`. |
| Xcode: `Multiple commands produce …/Info.plist` | `Info.plist` is both copied as a resource and processed. Use the XcodeGen project, or remove it from Copy Bundle Resources and set Generate Info.plist File = No. |
| Xcode runs old code | You're building a different copy of the project. Check a file's Full Path in the File Inspector (⌥⌘1). |
